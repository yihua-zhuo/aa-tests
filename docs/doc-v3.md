## 一、输入采集与预处理（1–10）

1. **预检前移到上传端**：在上传或拍照时就跑清晰度、反光、倾斜预检，不合格当场提示重拍，不要等入队后才给出 `retake`（§7.1）。
2. **`retake` 文件跳过级联**：反光严重、分辨率过低的图，增强也救不回来。直接返回重拍结论，省下恢复预算（§11.1）。
3. **几何矫正按信号自动开启**：`OCR_PREPROCESS_GEOMETRY` 默认为 0。可改成 skew > 3° 或检测到透视时自动启用，并用基准验证收益（§7.2）。
4. **文档四边形检测与透视裁切**：手机照片先去掉桌面背景，再做检测，减少背景误检和无效像素。
5. **弯曲页专用展平模型**：文档承认深度展平尚未接入（§7.2）。仅在弯曲信号触发时启用，遵循"基准不提升则不合并"（§20.3）。
6. **去模糊候选**：对清晰度低但像素足够的图，把去模糊加入光度候选，沿用"数字 token 不丢才采用"的自证规则（§18.16 #13）。
7. **反光区域局部处理**：对反光区单独标记，并提示补拍一张不同角度的图，不要对整图做过度增强。
8. **分块自适应二值化**：为阴影页增加 Sauvola 或 Niblack 这类局部阈值候选，不只用全局 Otsu。
9. **位图小字用上采样，不用 DPI**：DPI 只对 PDF 重新渲染有意义。对 `small_text` 的图片输入，加入超分或 Lanczos 放大到约 24px 字高的候选。
10. **印章压字的颜色分离候选**：把红通道从"实验变量"升级为针对红章、红色底纹的正式预处理候选，用盲测集确认收益（§13.4）。

## 二、模型与路由（11–19）

11. **关键字段字符集约束解码**：金额区域只允许 `0-9 , . - ( )` 和货币符，编号区域限定字母数字。这能直接减少 O/0、l/1、`,`/`.` 混淆，结果仍只作候选证据。
12. **两档模型**：首轮用 medium 保速度，区域复认和整页恢复用 server 大模型。裁剪区域很小，大模型的成本可以接受（§4.1、§17.4）。
13. **区域复认第二遍换互补模型**：同模型重读只算 `confirmed_same_engine`，不能降低关键字段风险（§18.15 #33）。第二遍换模型能提高独立证据比例，减少无谓复核。
14. **按业务类型先验路由**：类型目前在识别后才判定（§10.4）。可以结合来源系统或文件名提前判定，发票、回单直接走 `structure`，合同走 `auto`，省掉一次失败再恢复。
15. **固定模板 ROI 识别**：对高频模板缓存字段位置，只识别感兴趣区域，既提速又稳定字段定位。
16. **VLM 先小范围灰度**：只用于 `conflict` 的关键字段和手写区域，用 shadow 模式量化净收益后再扩大（§14.5、§20.2）。
17. **接入手写、印章、签名专用识别**：目前未配置 `OCR_SPECIALIZED_URL` 时这些块为空文本（§20.1）。接入后对手写字段设更严格的复核门槛。
18. **补齐竖排与多语言 profile**：竖排语义文档标为待做（§20.3）。同时把日文、韩文、阿拉伯文语料纳入基准，让最差分组门禁能覆盖。
19. **Camelot 对照数字 PDF 表格**：数字页没有 OCR 成本。pdfplumber 与 Camelot 的单元格不一致处直接标记，作为低成本的独立证据（§17.5）。

## 三、表格与字段（20–29）

20. **超宽表横向分带 OCR**：文档明确"尚未实现"（§20.3），可配合列中心和表头对齐。
21. **无框线候选网格引导切分**：候选网格置信高时，用它引导单元格切分和复认。只做提示，不改文本（§8.3）。
22. **续表继承列类型**：`repeatedHeader` 或续表链成立时，把上一页的 `columnSchema` 传给无表头的续表页，让列类型校验在续页也生效（§8.2、§9.2）。
23. **合计校验的舍入容差**：按币种小数位和税率舍入规则设容差，减少合计行误报，降低无效复核率（§9.3）。
24. **扩充独立校验规则**：在已有校验位基础上增加日期先后（开票日 ≤ 到期日）、发票代码与号码位数、手机号、邮编、车牌等（§9.4）。
25. **字段标签同义词词典**：合计金额、价税合计、Total、Amount Due 归一到同一字段，提高关键字段召回和 schema 覆盖率。
26. **标签—值几何配对**：按"右侧或下方最近"关联标签和值，而不是靠全文包含，与字段强命中口径保持一致（§13.2）。
27. **校验位失败时做单字符混淆搜索**：对带标签的身份证、账号、IBAN，尝试 0/O、1/l、8/B 等单字符替换。恰好只有一个替换能通过校验时，作为候选证据提交人工确认，不自动改写。
28. **用算术冲突定位可疑单元格**：合计与明细只差一个混淆替换时，优先复认这个单元格。这比按低置信度挑 4 个单元格更有针对性（§11.3）。
29. **单元格复认配额动态化**：`OCR_CELL_MAX_CANDIDATES` 固定为 4。可按表规模和冲突数量调整，并优先给涉及算术冲突的行。

## 四、质量评估与级联恢复（30–39）

30. **恢复成功率分桶**：目前全局 Beta 平滑（§11.2）。按"文档类型 × 问题类型 × 引擎"分桶统计，样本够多时跳过无效阶段更准。
31. **空白页快速短路**：全空白、全黑、加密、损坏页直接判定，不进入级联。
32. **按类型分配级联预算**：财务单据可以多给一个阶段，普通附件只给一个，而不是统一 `MAX_STAGES=3`、180 秒（§17.3）。
33. **质量权重用标注学习**：文档待办 #30 提到权重仍是启发式（§20.2）。在 calibration 子集上拟合各信号权重，并按文档类型分模型。
34. **`gate.passed` 接入注册表**：目前晋级仍靠人工确认（§18.15）。接入后，晋级要同时满足门禁通过和显著性检验。
35. **复核队列按风险排序**：用业务损失权重（金额/账号 8、日期 4…，§13.2）乘以不确定性排序，不要按 FIFO，让高风险错误更早暴露。
36. **复核 UI 一键采纳候选**：展示字段 crop 和 N-best 候选，采纳后写入独立修订表（§15）。这样缩短单份复核时间，也提高修订数据密度。
37. **静默错误审计的分层分配**：现在按文件类型抽样（§14.8）。对高风险类型提高比例、低风险类型降低，用 Neyman 分配收窄 Wilson 区间。
38. **PDF 生成器作为交叉验证先验**：把 PDF Producer 元数据与历史 `text_layer_mismatch` 率关联，对高发来源提高抽样率（§5.2）。
39. **最差分组自动补样本**：门禁指出"最差分组 CER（语言：ja）"时，自动把该分组送入主动学习抽样（§13.3、§14.1）。

## 五、性能与吞吐（40–52）

40. **sidecar 水平扩展与批处理**：单进程用锁串行抽取（§4.1），这是最大吞吐瓶颈。多副本加负载均衡，有 GPU 时启用识别批处理。
41. **按引擎分池**：若 worker 是单队列轮询，大扫描 PDF 会阻塞 Office 小文件。Paddle 与 Docling/native 分开队列和并发。
42. **优先级与公平调度**：交互式上传优先，基准、反馈回填、批量任务降级，并按工作区做公平调度。
43. **队列存储评估**：SQLite 多 worker 并发写时，至少开启 WAL 并做批量写。规模更大时评估 PostgreSQL 或 Redis 队列。
44. **推理加速**：用 ONNX Runtime、OpenVINO 或 TensorRT，配合 FP16/INT8 和识别 batch，先在基准上对比精度损失。
45. **渲染与 OCR 流水线化**：pypdfium2 渲染和 OCR 做生产者—消费者重叠，并缓存已渲染页，让相同 DPI 的恢复阶段不再重复渲染。
46. **页级与区域级缓存**：缓存键从整文件 SHA-256 细化到页哈希。合同修订版或周期性报表只改几页时，其余页可复用（§12）。
47. **模板页眉页脚跳过识别**：跨页重复的页眉页脚已能被标记（§8.2）。对已知模板从第 2 页起遮罩或复用结果，减少识别量。
48. **预检先用缩略图**：在长边 ≤ 1024px 的缩略图上算清晰度、反光、阴影，再决定是否需要全分辨率分析。
49. **历史驱动的初始 DPI**：某来源历史上常"200 → 恢复到 300"时，首次直接用 300，省下一次恢复。清晰文档则用 150 提速（§7.2）。
50. **页级恢复而不是整份重跑**：从接口看，`/extract` 只有 `mode` 和 `dpi`，没有页参数（§4.4）。给恢复阶段加 `pages` 参数，只重跑问题页。
51. **逐页流式持久化与单页重试**：长 PDF 每完成一页就落库，UI 先展示已完成页，失败页只重试该页，避免 300 秒超时丢掉整份结果。
52. **大图限边长**：12–80MP 的照片先限制长边（如 ≤ 4000px）再检测，降低检测耗时。需先用基准确认字级精度不下降。

## 六、数据与治理闭环（53–60）

53. **扩充真实语料**：目前只有 21 个合成样本（§13.1）。按文档 Phase 2 目标，每类至少 200 份审核样本，并包含传真、手机照、多栏、复杂表。
54. **难例挖掘闭环**：把 `model_disagreement`、人工修订、审计确认的错误样本自动入语料，并按模板族切分，防止同一模板泄漏到盲测集（§13.1.1）。
55. **中文与数字专项微调**：用 `ocr_field_revisions` 的修订数据训练，经注册表 shadow → canary → 晋级的路径上线（§14.5、§20.3 Phase 2）。
56. **漂移自动响应**：`warn` 或 `critical` 时，自动对偏移最大的桶补抽样，并在该桶上跑小基准复核阈值 profile，不只发告警（§14.3）。
57. **优化台账与 shadow 联动**：按 `expectedGain / cost` 排期，上线前用 shadow 和 McNemar 配对检验，一次只改一个变量，实际收益回写台账（§13.5、§14.4）。
58. **看板用真实错误率替代代理指标**：现在的 `confidenceRiskProxy` 和 `revisionObservedRate` 不是真实 CER（§14.2）。用审计和修订样本估计字段错误率，并和代理指标并列展示。
59. **标注质量升级**：语料 v2 引入行/字符 bbox、双标注与仲裁，沿用修订质检与单人标注降权机制（§18.15 #69、§20.3）。
60. **灰度按组织与类型分流，并加滚动窗口**：文档标注滚动窗口仍待补（§20.2）。分流后再做显著性检验，避免小样本波动触发晋级或回滚。
