# OCR 系统现状评估与识别率提升改造建议

评估对象：《文档智能与 OCR 完整方案（V2）》\
评估重点： OCR 文字识别准确率、复杂文档识别能力、关键字段准确性、表格识别能力、识别结果可信度及后续开发优先级。

## 一、总体评估结论

我的总体判断是：

当前系统已经具备比较完整的企业级 OCR 工程架构，但下一阶段不应该继续以增加管理模块、监控模块和外围功能为主要开发方向，而应该转向以真实识别准确率为中心的算法升级、训练数据建设、多模型协同和识别结果验证。

目前的架构思路是正确的，而且覆盖面较广。它并非简单地调用一个 OCR 引擎，而是形成了：
- 原生文本抽取与 OCR 混合识别。
- PaddleOCR 与 Docling 双侧车架构。
- PDF 按页、图片按区域的识别路由。
- 图像预检、图像增强和自适应 DPI。
- 统一文档中间表示 DIR。
- 表格检测、单元格识别和业务字段校验。
- 低置信区域复认和预算级联。
- 质量评估、基准测试和发布门禁。
- 人工修订、反馈样本池和主动学习。
- 模型注册、灰度发布、自动回滚和生产质量监控。

这些能力在主文档中均有明确设计，文档也声称 V2 骨架及 P0、P1、P2 规划能力已经上线。需要注意，这属于方案中的落地状态说明，并非我对实际运行环境、代码和生产识别效果的独立验证。

## 第一组：训练数据与基准体系（1—12）

这是我认为最值得优先投资的部分。

当前系统已经有 CER、WER、数值 CER、字段准确率、表格 TEDS、置信度校准和历史基准等指标，但文档承认语料规模较小。继续开发复杂算法之前，应该先保证我们能够可靠发现算法是否真的变好。

### 特别建议：第 25 项应当成为核心算法改造

当前的思路主要是生成有限数量的增强图，然后通过识别评分决定是否采用。

我建议升级为：

多候选图像增强决策系统

原始图片

图像质量诊断

模糊 / 阴影 / 反光 / 倾斜 / 噪声 / 小字

候选 A

灰度增强

候选 B

去阴影增强

候选 C

超分辨率恢复

候选 D

二值化增强

多模型识别及候选质量比较

选择最佳识别证据

保存原始图、增强图、识别结果和坐标变换

这里有一个重要原则：不能单纯以 OCR confidence 作为候选图像的选择依据。不同增强方法可能同时提高置信度，却生成错误字符。因此应该结合多模型一致性、文字覆盖率、结构约束及已有标注基准进行比较。

### 建议重点实施多模型识别

当前方案的局部复认，主要解决的是单次识别结果不确定的问题。

但同一个 OCR 模型重复识别同一个区域，可能会反复犯相同错误。增加 DPI、调整边距或切换增强方式，并不能确保解决模型本身的识别偏差。

建议引入下面的架构：

多引擎协同识别

同一原始文字区域

OCR A

PaddleOCR

OCR B

独立架构引擎

OCR C

领域微调模型

OCR D

VLM 候选识别

字符级、文本行级和字段级结果对比

结果处理

一致

进入已验证候选

分歧

触发上下文复认

高风险

人工复核

我的建议是不要让所有模型在所有文件上无差别运行，而是按错误类型、区域类型及预期收益分配模型。

另外，两个模型的结果相同不代表一定正确。模型之间如果共享训练数据、识别结构或前处理方式，可能存在相关性很高的共同错误。因此，候选融合时必须考虑模型独立性，而不能简单采用多数票。

| 47   | 增加分段和段落级文本校验    | 比对文本区域、段落、标题和正文的逻辑关系     | 减少文本乱序和漏段         | P1     |

特别强调第 46 项：语言模型不能仅仅因为某个词更符合语言习惯，就把图像中真实存在的字符替换成另一个词。

应该建立双轨结果：

```

    100,000

OCR 候选：
    100,000
    1OO,000
    100,O00

语义验证：
    金额字段格式校验
    上下文校验
    数值格式校验

结果：
    原始文本不变
    候选排序保留
    证据充分时标记候选
    不确定时提交人工复核
```

这比直接使用大语言模型改写识别文本可靠。

# 三、我认为当前开发计划还存在的五个方向性问题

以上 65 条是具体功能建议。除此之外，我认为还有五个需要在架构层面修正的问题。

## 3.1 问题一：不要继续把置信度当作识别准确率

当前质量评估已经有平均置信度、低置信行比例、文本覆盖率、表格完整性、字段校验等 13 项信号。总体方向很好。

但需要注意：

OCR 引擎置信度高，不代表识别结果正确。

例如：

原始图片：

```
发票金额：12800.00
```

OCR 结果：

```
发票金额：128O0.00
```

如果 OCR 模型对字母 O 的置信度很高，单纯依赖置信度可能无法发现错误。

建议将质量体系分成三个独立层次：

| 质量层次 | 评价对象                 | 核心指标                         |
| -------- | ------------------------ | -------------------------------- |
| 识别质量 | 字符是否识别正确         | CER、WER、字符准确率             |
| 结构质量 | 区域、行、表格是否正确   | 检测 F1、TEDS、单元格准确率      |
| 业务质量 | 金额、编号、日期是否正确 | 字段精确率、字段召回率、业务损失 |

另外，建议调整两个现有生产代理指标：
- `cerProxy = 1 - average confidence` 不应该直接以 CER 的形式展示，建议改名为 `confidenceRiskProxy`。
- `fieldErrorRate` 使用人工修订比例估算，也不等于真实字段错误率。建议改名为 `revisionObservedRate`。

真正的生产 CER 应该通过定期抽样、人工标注和真实 Ground Truth 计算，而不是从模型置信度推断。

## 3.2 问题二：当前级联策略过于依赖单次质量评分

文档目前采用质量评分、期望收益门控以及保留最高质量分结果的策略。默认最大 3 个阶段、总预算 180 秒。

document-intelligence.md



这里存在一个重要隐患：

同一质量模型既参与判断是否需要恢复，又参与选择恢复后的最佳结果，容易出现优化目标不一致的问题。

例如：
- 模型 A 识别 100 个字符，漏掉 5 个字，置信度 0.98。
- 模型 B 识别 105 个字符，全部正确，置信度 0.94。

只看置信度可能错误选择 A。

建议修改为分层结果选择：
1. 第一层：检查是否有关键区域缺失。
2. 第二层：比较字符覆盖率及文本行完整性。
3. 第三层：比较关键字段候选及字段校验结果。
4. 第四层：比较表格结构和阅读顺序。
5. 第五层：利用校准后的模型置信度进行排序。
6. 最后：如果存在关键字段冲突，提交复核而不是强行选择。

特别是金额、账号、证件号等关键字段，应该使用独立的硬门槛。

## 3.3 问题三：多模型应该独立于现有级联设计

建议将目前的 OCR 级联设计升级为两层：

第一层：多模型候选生成。
- 原始 OCR 模型。
- 第二 OCR 模型。
- 领域微调模型。
- 不同预处理生成的候选模型。
- 专用字段识别模型。

第二层：结果验证与选择。
- OCR 文字一致性判断。
- 图像区域证据判断。
- 字段类型及业务规则判断。
- 候选置信度校准。
- 高风险结果人工复核。

这意味着模型负责提供候选，独立验证模块负责决定证据是否充分。

不要让某一个 OCR 模型同时承担识别、判断和纠错全部责任。

## 3.4 问题四：模型自动晋级需要更严格的统计检验

目前文档中的注册表允许在满足最低样本数量、候选模型领先幅度和生产表现要求时自动晋级或回滚。

但其下一步计划也提到，需要引入滚动窗口和统计显著性检验。

document-intelligence.md



建议正式加入：
- 按文档类型分别计算准确率变化。
- 按语言分别计算准确率变化。
- 按退化程度分别计算准确率变化。
- 采用配对样本比较。
- 引入 Bootstrap 置信区间。
- 对二分类结果采用 McNemar 检验。
- 设置最小业务收益。
- 限制关键文档类型的准确率下降。
- 样本量不足时禁止自动晋级。

尤其不建议仅依据 20 个样本、1% 的领先幅度就普遍自动晋级。具体门槛需要根据实际样本数量、业务风险和统计功效确定。

## 3.5 问题五：VLM 不能被当成 OCR 错误的万能修复器

目前 VLM、专用区域识别和 Camelot 已经接入协议与级联，但需要配置外部服务才真正启用。

建议对 VLM 进行独立的效果验证。

VLM 可能出现：
- 补全图中不存在的字符。
- 将模糊字符理解为符合上下文的另一个字符。
- 将表格中的相邻单元格内容混合。
- 误读金额、小数点和编号。
- 将不清楚的手写内容推测为合理词语。

所以应该明确规定：

VLM 只提供候选及视觉证据，不负责自动确认事实。

对关键数字和编号，必须有原始图像定位、独立 OCR 验证或人工确认。

## 我的最终评价

当前系统已经不缺少基础的工程架构，也不缺少各种 OCR 周边管理模块。

真正缺少的是三个核心竞争力：

第一，真正针对错误进行优化的能力。

不只是知道 OCR 结果置信度低，而是能够精确区分文字检测错误、字符识别错误、语言模型错误、结构错误和图像质量错误。

第二，能够适应业务文档的多模型识别能力。

不再依靠单一 PaddleOCR 和简单重试，而是让不同模型、不同增强方法、不同识别策略针对不同问题发挥优势。

第三，真实有效的持续学习能力。

人工修订不应该仅停留在记录和复核，而应该转化为高质量数据，持续用于模型训练、实验、评估和版本升级。

我认为当前最大的开发方向调整应该是：

> 从「功能完整的 OCR 文 档处理平台」升级为「以真实识别准确率为核心、具备多模型协同、自适应增强和持续学习能力的智能 OCR 平台」。

这才是下一阶段真正值得投入的方向。
